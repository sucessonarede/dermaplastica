 2. RODAR NA SUA MAQUINA
===============================================================================

  Abra o Terminal e cole:

    cd /Users/marciaoliveiraalves/Documents/CLAUDE/Projects/Dermalift
    npm run dev

  Depois abra:  http://localhost:5000

  Para parar o servidor:  Ctrl + C  na janela do Terminal
  Deixe a janela ABERTA enquanto estiver usando.

  ---------------------------------------------------------------------------
  Se for a primeira vez num computador novo:

    npm install       (instala as dependencias)
    npm run setup     (pergunta a senha do banco e monta o arquivo .env)
    npm run dev

  O "npm run setup" pede duas coisas e mostra asteriscos no lugar do texto:
    1) a senha do banco (Supabase > Settings > Database)
    2) a service_role key (Supabase > Settings > API) - pode pular com Enter,
       mas sem ela o upload de fotos nao funciona

  Ele testa a conexao no fim e lista as tabelas com a contagem de registros.

 3. PUBLICAR NA VERCEL
===============================================================================

  PASSO 1 - Enviar o codigo para o GitHub

    cd /Users/marciaoliveiraalves/Documents/CLAUDE/Projects/Dermalift
    git push -u origin main

    Se o push for recusado porque o repositorio ja tem um README:
      git pull --rebase origin main
      git push -u origin main

  PASSO 2 - Criar o bucket de arquivos no Supabase

    Supabase > Storage > New bucket
      Nome: dermalift
      Public bucket: DESMARCADO
    Sem esse bucket, o upload de fotos de pacientes falha.

  PASSO 3 - Importar na Vercel

    Acesse vercel.com/new
    Import Git Repository > sucessonarede/dermaplastica
    Framework Preset: Other
    NAO altere Build Command nem Output Directory (vem do vercel.json)

    Antes de clicar em Deploy, cadastre as variaveis da secao 4.
    Marque as tres environments (Production, Preview, Development).

  PASSO 4 - Conferir

    Abra  https://SUA-URL.vercel.app/api/health
    Deve retornar: {"ok":true,"env":"production"}

    Depois: faca login, abra um paciente, gere um orcamento.

===============================================================================

  Esse arquivo NAO vai para o GitHub (esta no .gitignore) - e proposital.

  Para ver o .env: no Finder ele fica oculto. Use Cmd + Shift + . para

  ---------------------------------------------------------------------------
  CADASTRAR NA VERCEL:

    DATABASE_URL                 conexao do POOLER, porta 6543
    SESSION_SECRET               copie do seu .env
    SUPABASE_URL                 https://zjqxytnwjyvdafnrujph.supabase.co
    SUPABASE_SERVICE_ROLE_KEY    copie do seu .env
    SUPABASE_STORAGE_BUCKET      dermalift
    PRIVATE_OBJECT_DIR           private

  NAO cadastrar na Vercel:

    DIRECT_URL                   so serve para migracoes rodadas por voce

  ---------------------------------------------------------------------------
  ATENCAO A PORTA DA CONEXAO:

    6543  = transaction pooler -> use na aplicacao (local e Vercel)
    5432  = session pooler     -> use so para migracoes (DIRECT_URL)

  Se usar a porta errada na Vercel, o Supabase derruba o banco por excesso
  de conexoes. Cada acesso ao site abre uma conexao nova.

  ---------------------------------------------------------------------------
  A service_role key e SECRETA. Ela so existe no backend, nunca e enviada
  para o navegador. Nao publique em lugar nenhum.

===============================================================================

  O banco JA EXISTE e esta POPULADO com os dados reais da clinica.
  E o mesmo banco que era usado no Replit.

  >>> NAO RODE "npm run db:push" POR HABITO <<<

  Esse comando compara o arquivo de schema com o banco e aplica as
  diferencas. Se houver qualquer divergencia, ele pode ALTERAR ou REMOVER
  colunas que tem dados dentro.

  Se um dia precisar mudar o schema, rode primeiro SEM confirmar:

  de producao. Paciente que voce cadastrar para testar vai aparecer para a
  clinica.

  Se for testar bastante, crie um projeto separado no Supabase e aponte o
  .env local para ele.

  e PostgreSQL em producao           que rodar em ambiente serverless

 7. FUNCIONALIDADES NOVAS
===============================================================================

  MAPA FACIAL NO PROTOCOLO DERMALIFT
  ---------------------------------------------------------------------------
  Cada coluna de pilar tem um rosto clicavel acima da lista de procedimentos.
  Voce marca as areas que serao tratadas naquele pilar.

  Como funciona:
    - Clicar num lado marca os DOIS lados (malar, olheira, mandibula...)
    - Para marcar so um lado: Alt + clique
    - "Marcar todas" e "Limpar" no canto direito da legenda
    - Tudo marcado vira um unico rotulo: "Todas as areas"
    - Acima de 6 areas, a legenda resume com "+N"

  A marcacao e INDEPENDENTE dos procedimentos: marcar area nao seleciona
  procedimento nem mexe em valor. E ilustrativo, para o paciente entender
  onde sera tratado.

  Fica salvo junto com o orcamento e aparece na apresentacao, num slide
  chamado "Areas do seu tratamento", antes do slide do plano. So aparecem
  os pilares que voce marcou.

  Observacao: algumas areas se sobrepoem no desenho (a olheira encosta no
  malar). No ponto de sobreposicao, o clique pega a area que esta por cima.
  Clicando numa parte livre, pega a certa.

  GRAFICO DE FATURAMENTO NO DASHBOARD
  ---------------------------------------------------------------------------
  Barras dos ultimos 6 meses, somando o valor dos orcamentos por mes.
  Passando o mouse aparece o valor cheio e a quantidade de orcamentos.
  Meses sem orcamento aparecem vazios de proposito.

 10. PROBLEMAS COMUNS
===============================================================================

  "Erro 500 em tudo" depois do deploy
    Falta variavel de ambiente na Vercel.
    Veja: Deployments > clique no deploy > Functions > Logs

  "too many connections" ou o banco travando
    Voce usou a conexao direta (5432) na Vercel.
    Troque pela do transaction pooler (6543).

  Login desloga sozinho
    SESSION_SECRET faltando ou diferente entre as environments.
    Use o mesmo valor nas tres.

  Upload de foto retorna erro
    Falta a SUPABASE_SERVICE_ROLE_KEY, ou o bucket "dermalift"
    nao existe no Supabase Storage.

  Pagina em branco ao recarregar uma rota interna
    O arquivo vercel.json nao foi commitado.

  Git reclamando de "index.lock"
    Apague o arquivo .git/index.lock e repita o comando.

  Senha do banco nao funciona
    Se voce copiou do painel do Supabase e ela tem asteriscos, e a versao
    mascarada. A senha real esta nos Secrets do Replit (se o projeto ainda
    existir) ou pode ser resetada em Supabase > Settings > Database.
    Resetar nao apaga dados.

  Acento sumindo no nome da clinica
    O nome vem do cadastro em Configuracoes. Corrija por la.

  O rosto do mapa facial nao aparece
    Reinicie o servidor. A pasta client/public e lida so na inicializacao.
